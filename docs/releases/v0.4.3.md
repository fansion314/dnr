# dnr v0.4.3

This release adds a combined macOS ARM64 prebuilt package and Homebrew delivery,
and includes the desktop zoom extension. DNP remains format v4; existing v4
applications stay compatible.

## Clean-build fix

v0.4.2 was tagged but its runtime CI jobs failed before publication: Git silently
skipped upstream patches inside a fresh nested build directory. `prepare` now
creates a separate Git context for each copied upstream, and a regression test
verifies actual patch application and repeat execution inside a parent checkout.
The v0.4.2 tag and failed runs remain unchanged. A fresh prepared snapshot passes
`cargo fetch --locked` for macOS ARM64 before this release commit.

## macOS installation

The macOS archive `dnr-0.4.3-macos-arm64.tar.gz` contains both `dnr` (system
WebView backend) and `dnc`, with documentation and license notices. It targets
Apple Silicon on macOS 15 Sequoia or later and uses only system dynamic libraries.
The executables use ad-hoc signatures, without Developer ID signing/notarization.

After the macOS build and tap publication jobs complete:

```sh
brew tap fansion314/dnr
brew install fansion314/dnr/dnr
```

The formula downloads the versioned Release archive, verifies SHA-256, and
installs both commands without compiling locally. The dedicated tap is updated
only after an installation test against the public Release download succeeds.

## Desktop zoom

- `dnr zoom set 1.25` sets user-wide content zoom for newly started applications.
- `Deno.desktop.setZoomFactor(1.2)` applies an application-wide multiplier;
  combined with 1.25 user zoom, this gives 150% content zoom.
- Native Cmd/Ctrl `+`, `-`, `0` shortcuts update the application multiplier across
  its windows. Reset preserves the user's global setting.
- These are dnr extensions, not APIs from the pinned upstream Deno Desktop.

## Validation and limits

Before release, the packaging helpers passed checksum, tag, immutable asset,
formula update and retry tests. A local archive built from the existing 0.4.1
development executables passed real Homebrew installation, TS/resource/package
execution and signature checks; this is packaging-path evidence, not a 0.4.3
release-binary result.

The committed zoom implementation has macOS WebView and Linux dual-backend
debug/runtime and GUI evidence in `VALIDATION.md`. The release jobs build fresh
macOS WebView and Arch dual/CEF/WebView binaries and run their native runtime
tests. Their final results and binary hashes are recorded in Actions/Release,
not predicted in this release-preparation commit. No new Wayland or hardware
GPU acceptance is claimed.

See [macOS delivery](https://github.com/fansion314/dnr/blob/v0.4.3/docs/MACOS-RELEASE.md)
and [zoom API and limits](https://github.com/fansion314/dnr/blob/v0.4.3/docs/ZOOM.md).
