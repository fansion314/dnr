# dnr v0.5.0

This release improves cache management and remembers application window sizes,
while allowing hidden windows to release their native page and recreate it later.
DNP remains format v4; existing packages do not require repacking.

## Cache management

- `dnr cache info` now summarizes the cache location, logical size, path and
  generation counts, and index freshness. Sizes use decimal B/KB/MB/GB;
  `--json` retains integer byte counts and full identifiers.
- Last-use timestamps are tracked asynchronously by canonical application path,
  independently of catalog updates. Inspection does not refresh usage history.
- `dnr clean` aliases `dnr cache clean`. Use `--before 2026-09-01`,
  `--max-size 2GB`, or `--path-regex '^/private/'`, with optional `--dry-run`.
  Selectors intersect; capacity cleanup uses oldest paths first and skips paths
  with active generations. Logical bytes are not physical disk space reclaimed.

## Shorter native sidecars

New native installations use `app.dnp.unpacked/<group>/root/<logical-path>`.
Version/content/platform identities remain in receipts, while original resource
and symlink relationships are preserved. Existing sidecar layouts remain readable.
Running installations cannot be overwritten; the user cache keeps its generation
isolation. A sidecar contains one content version and target platform.

## Application preferences

- Zoom and the main window's normal content size are remembered by appId across
  upgrades and moves. Additional windows opt in with a stable `stateKey`.
- Changes share a five-second debounce and are flushed on normal or explicit
  runtime exit. Old application zoom files are imported; writes merge changed
  fields across processes. Preferences are separate from disposable caches.
- `Deno.desktop.setStatePersistence({ zoom: false, windowSize: false })`
  disables restoration and saving without deleting previous preferences.
  `rememberSize: false` disables size memory for one window.

## Breaking change: closing and hiding windows

The default `closeBehavior` is now `"hide"`, with native resources released after
five minutes. Set `closeBehavior: "destroy"` to retain the previous default.

`hiddenWindowPolicy` supports `{ mode: "immediate" }`, `{ mode: "keep" }`, and
`{ mode: "delayed", delayMs: 300000 }`. Native close and `hide()` use the policy;
minimization does not. `show()` or `focus()` cancels the timer or recreates the
native instance behind the same logical BrowserWindow, restoring host bindings,
listeners, configuration and the last host navigation entry.

Recreation reloads the page: DOM, page JavaScript memory, history and unsaved input
are not preserved. Choose `keep` if the application needs that state. `destroy()`
remains permanent. Released windows do not keep an otherwise idle application
alive. Shared backend processes may remain; native WebGPU handle protection is
preserved rather than invalidating exported handles.

## Packages and verification

Tagged Actions build the macOS ARM64 archive containing dnr and dnc, plus separate
Arch x86_64 dual, system-CEF, WebView and dnc packages. These builds and their final
asset checksums are recorded in Actions and Release assets after publication.

Pre-release debug verification covers macOS ARM64 WebView and native Linux x86_64
under KDE X11 software rendering, including window release/recreation, restored
bindings, restart persistence, disabled memory settings and actual native close.
Details and limits are recorded in [VALIDATION.md](https://github.com/fansion314/dnr/blob/v0.5.0/VALIDATION.md).
Linux Wayland, real GPU rendering, and mixed-DPI monitor migration were not covered.
The macOS WebView native WebGPU-handle export limitation also reproduces on 0.4.3;
that path is not claimed as newly verified.
