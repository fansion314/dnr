# dnr v0.3.0

This release introduces DNP format v3, persistent compilation caches, and a Linux
runtime that includes both system CEF and WebView.

## Compatibility

- dnr and dnc now support only format v3. Repack v1/v2 applications from their
  prepared source directories with dnc 0.3.0. Upgrade Pi to its v3 DNR release
  together with the runtime.
- Applications continue to run with full permissions. Application processes and
  storage identities remain separate.
- The default Linux runtime requires both CEF and WebKitGTK system libraries.
  CEF-only and WebView-only packages remain available.

## Runtime and packaging

- `dnr --backend auto|system-cef|webview app.dnp` selects the desktop backend.
  Auto prefers CEF and falls back to WebView on ABI/resource checks or returned
  initialization errors. Explicit selection does not fall back. GUI startup
  remains lazy; ordinary CLI commands do not open a display.
- V3 uses compact binary metadata and short native payload paths. Declared native
  groups reuse validated adjacent installations or persistent user caches.
- V8 code and TypeScript/JSX transpilation caches are enabled for v3 applications.
  Cache generations follow package path/content changes and retain active leases.
- `dnr install`/`dnc install` support adjacent native groups and full directory
  installations. `dnr cache` manages the optional cache catalog.

records accompany each package.

## Validation

The Linux dual release passed 58 workspace tests, 20 runtime/native tests, real
GUI selection and injected CEF failure fallback checks for scripts and DNPs,
and KWin native-close checks for both backends. CEF API 14900 was validated
against system CEF 152.0.6. See `VALIDATION.md` for exact commands and boundaries.
Mac ARM64 v3 validation is recorded separately; this release workflow publishes
Linux x86_64 packages. Missing ELF dependencies and process crashes are not
recoverable initialization errors.
