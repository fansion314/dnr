# dnr v0.2.0

This release adds format v2 native component groups, persistent caching, and a
standalone Arch package for `dnc`.

## Native groups and caching

- `dnc scan` suggests native groups and platform metadata for author review.
  Package the reviewed configuration with `--package-config`.
- Declare Node-API addons, FFI libraries, executables and their companion files
  together. Native loading or execution prepares the complete group on demand.
- Reuse verified persistent caches across launches, or prepare an adjacent copy
  with `dnr install app.dnp ./installed`. Inspect and clean caches with `dnr cache`.
- Stable group paths support module-relative resources, dependent shared libraries,
  and Deno/Node synchronous and asynchronous subprocess APIs.
- SHA-256 content identities isolate package versions. Process locks and leases
  coordinate concurrent preparation and keep active groups out of cache cleanup.
- Indexed path lookup and one-time group verification reduce repeated work.
  Ordinary VFS reads remain lazy and do not extract groups.

See [native packaging](https://github.com/fansion314/dnr/blob/v0.2.0/docs/NATIVE-PACKAGING.md)
for configuration, cache locations and compatibility boundaries.

## Compatibility and upgrade

**New `dnc` outputs format v2, which requires the new runtime.** Upgrade `dnr`
before distributing newly packed applications. The new runtime continues to read
v1 packages with their original temporary native-library behavior.

For v2, packaged native entry points must be declared in the package configuration.
The scanner does not collect dependencies or determine resource boundaries for you.
Cache identities verify content integrity; they do not authenticate a publisher.
Applications still run with full user permissions.

## Arch Linux / CachyOS downloads

Choose one runtime:

- `dnr-0.2.0-1-x86_64.pkg.tar.zst`: system CEF.
- `dnr-webview-0.2.0-1-x86_64.pkg.tar.zst`: WebKitGTK.

Install `dnc-0.2.0-1-x86_64.pkg.tar.zst` separately if you need to build application
packages. **Runtime packages no longer include `dnc`.** End users running existing
applications only need a runtime. The two runtime packages conflict with each other;
the standalone packager can coexist with either.

The release workflow builds generic x86_64 binaries in the official Arch container,
runs package and runtime tests, and publishes all three packages with SHA-256
checksums and build environment records. Source and binary recipes for all three
packages are in `packaging/aur`; inclusion here does not imply AUR registration.

Supported runtime targets remain macOS ARM64 and Linux x86_64. macOS users build
from source; this release workflow produces Linux packages. Other targets in package
metadata do not imply new runtime ports. System WebView/CEF libraries remain external
dependencies.

## Validation

Native macOS validation and the Linux release validation are recorded in
[VALIDATION.md](https://github.com/fansion314/dnr/blob/v0.2.0/VALIDATION.md).
Linux validation on CachyOS / KDE Wayland / NVIDIA covers both release backends:
16 runtime/native tests each, real GUI bindings, trays, exit and native-close
behavior, storage isolation, and real esbuild cold/warm/adjacent-cache execution.
Workspace tests, Clippy and real Arch packaging checks also passed.
CI includes `runtime_groups` alongside the existing runtime and native-library
tests; it does not replace the separately recorded real desktop checks.
