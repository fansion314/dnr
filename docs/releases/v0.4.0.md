# dnr v0.4.0

DNP format v4 adds optional window/Dock icons and application names to package
metadata. CLI applications can omit desktop metadata entirely. Repack v1–v3
applications with dnc 0.4.0 before upgrading their runtime; old full installations
must also be rebuilt. Upgrade the runtime and application packages together.

## Desktop icons

- `dnc --window-icon icon.png` embeds a bounded RGBA icon, reduced to at most
  128×128. No icon files are extracted at runtime and CLI use does not load GUI.
- Desktop manifests automatically reuse Linux PNG or macOS PNG/ICNS icons;
  optional `windowIcon` supplies a PNG override, including when Linux uses SVG.
- Linux CEF sets both titlebar and application icons. GTK identity is set before
  opening the display, including CEF initialization failure followed by WebView.
  GTK3/Wayland still resolves compositor icons through the installed desktop file.
- macOS can set the Dock icon directly from DNP metadata. The thin native `.app`
  launcher retains bundle entry/lookup/error handling and no longer passes icons.
  This macOS change has not yet received native build or Dock validation.

## Linux assets and validation

The release includes `dnr`, `dnr-cef`, `dnr-webview`, and standalone `dnc`
0.4.0-1 Arch/CachyOS x86_64 packages with SHA-256 files and build records.
The dual runtime retains optional GUI dependencies and lazy backend loading.

Native CachyOS/KDE Wayland verification includes 61 workspace tests, 21 explicit
runtime/native tests, 10 backend/fallback scenarios, and eight native-close cases.
Both Songjian backends displayed the application icon in the titlebar. See
`VALIDATION.md` for evidence and limitations. GitHub Actions independently builds
and checks all four Linux packages before publishing them.
